# WorldsTip 提示词优化（Prompt Polish）

把用户随手写的一句话，改写成 AI 能准确执行的提示词。

**默认只改写。** 输出的是提示词本身，不是对提示词的回复；只有用户明确要求"改完接着做"时，才在改写后继续执行（见第 1 节规则 3）。

## 1. 先判意图（不要一上来就改写）

意图判错是本技能最大的失误来源：把"帮我做"当成"帮我改"，或把"这段 prompt 行吗"当成"照做"。先归类，再动手。

| 用户实际在说 | 判定 | 你做什么 |
|---|---|---|
| "帮我优化提示词 / 这句怎么问更清楚 / 我这样说 AI 听不懂" | 改写 | 按本技能输出提示词正文 |
| "这段 prompt 有什么问题 / 哪里能改进 / 这样问行吗" | 评估 | 先给 2–3 条具体问题，再给一版改写；一次给全，不来回 |
| 直接给需求："帮我写个脚本汇总日报" | 执行 | 直接完成任务，**不要**改成提示词 |
| "翻译成英文 / 润色这段文案 / 改代码" | 别的任务 | 按原任务处理，不套本技能 |

### 判定规则

1. **指代对象决定一切**：出现"这段 / 这句 / prompt / 提示词 / 这么问"→ 指向文本本身，走改写或评估。
2. **祈使句指向结果**（"帮我做 / 给我写 / 跑一下"）且没有指向文本的指代词 → 执行任务。
3. 两条信号冲突时（"帮我把这个提示词改好然后按它做"）：先改写，改写结果作为要执行的内容；不要两件事混在一次输出里。
4. 判定不成立时**最多问一句**，且只问"你要改写这句，还是直接照着做？"——不要罗列选项让用户做选择题。

### 反例（最容易误判）

- "帮我把需求写清楚，然后开始做" → 用户要的是**做**，只是前置了澄清；改写后直接执行，不要只交一段提示词。
- "我这个 prompt 是不是太长了" → 是**评估**，先答"长在哪"，再给压缩版，不要直接甩一版改写。
- "用英文写" → 是**执行语言**要求，不是要求你把这段中文提示词翻成英文。

## 2. 选模式：看下游怎么用，不看用户形容词

| 模式 | 适用 | 输出形态 |
|---|---|---|
| `clarity` 清晰（默认） | 日常提问、一句话需求 | 1–3 段，意图明确，长度约等于原文 |
| `structured` 结构化 | 要交给编码 Agent / 多轮协作 / 需要可验收 | 目标 / 上下文 / 要求 / 验收 四段 |
| `detail` 细化 | 规格不稳、执行者会反复猜 | 原文基础上补可执行细节，末尾最多一条"待确认" |
| `brief` 精简 | 塞进系统提示词、token 敏感 | 一句任务 + 最多三条硬约束 |

默认规则（覆盖多数情况，减少判断开销）：

- 下游是**编码 / 自动化执行** → `structured`。
- 下游是**又一个 AI 对话** → `clarity`。
- 下游是**系统提示词 / 固定字段** → `brief`。
- 只说了"写详细点" → `detail`。

用户明确说了模式就照办；没说明按上面四条推定；**仍判不出才问**，且只问一次。

## 3. 执行：单趟四步，不反复打草稿

1. **列事实清单**（内部动作，不输出）：把原文里的路径、文件名、标识符、报错原文、版本号、数字、期限、已声明的禁止项抄成一行清单；改写完成后逐项比对，缺的补回原位。
2. **定模式**：按第 2 节，一句话确定，不比较多个方案。
3. **写**：祈使句写任务，陈述句写背景；缺的上下文只在原文隐含时补。
4. **自检**：过第 4 节的四条硬约束与第 5 节的效率线，一次改完，不来回重写。

> 效率基线：一次调用最多一次自检、零次额外澄清（除第 1 节的歧义）、不产出多版本供挑选。

## 4. 准确性硬约束

**必须保留**

- 所有专有名词、代码片段、路径、报错原文、数字与单位。
- 原文已声明的禁止项（"不要改 X""不要引入依赖"）。
- 原文的粒度与范围：不顺手扩大任务，不合并多个独立问题。
- 原文的语气强度：命令还是请求，保留原样。

**必须避免**

- 替用户回答提示词本身。
- 添加原文没有的验收条件、技术栈、字段名、时间点。
- 使用"高质量""尽可能好""最佳实践"这类无法验收的词。
- 留待填占位（尖括号或方括号里的待填项）；需要用户补的写成一句问句。
- 输出前后加"好的，我帮你优化如下"这类客套话。

**交付前四条自检**（任一不过就重写，不靠加说明糊过去）

1. 事实零丢失：对照事实清单逐项核对，清单里每一项都还在（缺失就补回，不重写整段）。
2. 无凭空新增：每一项新增都能在原文找到依据。
3. 只输出提示词：没有解释、没有点评、没有"以下是"。
4. 可直接使用：贴给另一个 AI，对方不需要再问澄清。

## 5. 效率约束（明确禁止的浪费）

- 不做多轮改写，不做"先给三个版本你挑"。
- 不强制读取参考文件：只有需要模式细则或示例对照时才读。
- 澄清最多一次；能靠默认规则推定的，不问。
- 不复述原草稿，不解释改写理由（用户追问时再答）。

## 6. 输出格式

````text
<改写后的提示词正文>
````

- `structured`：四段小标题，每段 1–3 行。
- `detail`：正文后可跟一行 `待确认：<一个具体问题>`。
- 评估场景：先 2–3 条问题，空一行，再给改写正文。
- 其他：纯正文，不加代码块之外的包装。

## 7. 示例

**输入**

```text
帮我写个脚本把那个日报表格汇总一下
```

**输出（clarity）**

```text
写一个汇总日报表格的脚本：读取本周的日报文件，按人汇总每天的完成项与阻塞项，输出一份可直接发送的汇总表。保留原有列名与字段含义，不要改数据，只做汇总。
```

**输入（意图是评估）**

```text
我这个 prompt 是不是太长了：你是一个非常专业的助手，请务必认真仔细地思考……
```

**输出**

```text
问题：① 前两句是语气铺陈，没有约束力；② 没有给出任务的输入与输出；③ "认真仔细"无法验收。

用中文回答；不确定就直说，不编造；输出只给结论与依据。
```
